# Session History Archive

This directory contains brief notes from each Claude Code session for searchable project history.

## Purpose

- **Session Continuity**: Help new Claude sessions understand what was done previously
- **Pattern Recognition**: Identify recurring issues or common workflows
- **Decision Tracking**: See why certain choices were made and when
- **Learning**: Build institutional knowledge across sessions

## File Format

Session notes use the naming convention: `YYYY-MM-DD_HHMM.md`

Example: `2025-10-24_1545.md` = Session on October 24, 2025 at 3:45 PM

## Content Structure

Each session note contains (10-20 lines):
- **Actions Taken**: Key activities during the session
- **Outcomes**: What was accomplished
- **Next Steps**: What should happen next
- **Blockers/Issues**: Any problems encountered

## Automatic Generation

Session notes are automatically generated by the `/update-docs` command when:
- Ending a session with significant work
- Before making git commits
- After major changes or discoveries

## Manual Creation

You can also create session notes manually:
```bash
# Copy the template
cp .claude/templates/session-note-template.md .claude/sessions/$(date +%Y-%m-%d_%H%M).md
# Edit with your session details
```

## Searching History

Find past work:
```bash
# Search all session notes for a keyword
grep -r "keyword" .claude/sessions/

# List sessions in chronological order
ls -lt .claude/sessions/*.md

# View recent sessions
tail -20 .claude/sessions/*.md
```

## Retention Policy

**Keep all session notes indefinitely**. They're small files (~500 bytes each) that provide valuable historical context.

## Example Session Note

```markdown
# Session: 2025-10-24 15:45
Duration: 45 minutes

## Actions Taken
- Fixed security vulnerability in ioctl handler
- Added bounds checking to prevent buffer overflow
- Updated SECURITY_AUDIT.md with fix details

## Outcomes
- CRITICAL-002 vulnerability resolved
- Driver now safe for userspace interaction
- All tests passing

## Next Steps
- Test with fuzzing tool
- Update documentation for remaining issues

## Blockers/Issues
- None
```

---

**Note**: Session notes complement `SESSION_STATE.md` (current state) and `START_HERE.md` (human-readable status). This archive provides historical context that those files don't capture.
